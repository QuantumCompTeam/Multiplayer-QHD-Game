## Full Findings

### Layer 2 — Spec-vs-Code

#### [SPEC-VS-CODE] CONTRADICTION — BLOCKING
- **Spec says:** Month-2 spec §4.4 — *"Classical symmetric profiles for the advantage baseline: only (D,...,D) and (H,...,H)... Best classical = 4/3."* compute_advantage contract: *"best_classical_payoff : float — max per-player payoff over all-classical symmetric profiles (D...D and H...H)."*
- **Code does:** `src/game/nash.py:154-167` — baseline is the classical **Nash equilibrium** payoff from `find_pure_nash` on the restricted {D,H}^3 game = (H,H,H) = 0.333, NOT the best symmetric profile (4/3).
- **Impact:** Spec definition → advantage = 4/3 − 4/3 = **0.0** (checkpoint fails). Code definition → advantage = 4/3 − 1/3 = **1.0** (checkpoint passes). The Month-2 RQ1 conclusion depends entirely on which definition holds.
- **Fix:** Reconcile. README §1/§5.2 ("NE_quantum − NE_classical") agrees with the **code**, so update Month-2 spec §4.4 to define the baseline as the classical NE. Treat as scientific-intent decision (see CLAIMS), not a pure doc edit.

#### [SPEC-VS-CODE] UNDOCUMENTED_DIVERGENCE — HIGH
- **Spec says:** Both specs fix the quantum strategy as `Q = U(0, π/2, π/2)` (Month-1 spec §6.1; Month-2 spec §2.4/§4).
- **Code does:** `nash.py:41` maps "Q" → `q_strategy(N) = U(0, π/N, π/N)` (`ewl.py:88-120`).
- **Impact:** Coincides at N=2 (π/2) so Month-1 tests pass unchanged. At N=3, (Q,Q,Q) is Nash only because Q was silently redefined to π/3; the spec's U(0,π/2,π/2) is NOT Nash at N=3. Documented only in a code docstring (`ewl.py:114-117`), no spec/README.
- **Fix:** Promote the π/N scaling of the quantum Nash strategy into the Month-2 spec / paper — likely the most important result so far.

#### [SPEC-VS-CODE] SILENT_ASSUMPTION — MEDIUM
- **Spec says:** Month-2 spec §4.4 return key `best_classical_payoff`.
- **Code does:** `nash.py:191` returns `classical_ne_payoff` (renamed + redefined); adds `classical_nash_profiles` not in the spec contract.
- **Impact:** Downstream consumers (Month-3 sweep, figure scripts) coded to the spec keys will KeyError or read the wrong field.
- **Fix:** Update spec §4.4 return contract to the implemented keys.

#### [SPEC-VS-CODE] UNDOCUMENTED_DIVERGENCE — LOW
- **Spec says:** Month-1 spec §8 + plan Task 9: `ghz_entangler` is a Month-3 stub (H+CNOT → QuantumCircuit, real-valued GHZ).
- **Code does:** `topologies.py:34` implements it now (Month 2) as X^⊗N → ndarray (complex-valued GHZ).
- **Impact:** Intentional — Month-2 spec §2.1 chose Option A (X^⊗N) and rejected Option B (H+CNOT). Reconciled in the newer spec; Month-1 plan is stale.
- **Fix:** Optionally mark the Month-1 plan as superseded by the Month-2 spec.

### Layer 3 — Claims-vs-Evidence

#### [CLAIMS] BLOCKING (same root as the spec contradiction)
- **Claim:** "Quantum advantage confirmed for N=3" (README §7; `n3_advantage.py` prints advantage = 1.0).
- **Source:** q_payoff (4/3) measured; classical-NE baseline (1/3) measured. But quantum NE payoff (4/3) **equals** the classical cooperative profile (D,D,D = 4/3), which is not an equilibrium.
- **Risk:** "+1.0 advantage" holds only under "vs classical equilibrium." Under "vs best achievable classical play" (spec §4.4 baseline) advantage = 0 — quantum gives no payoff gain, only equilibrium enforceability. Reviewer can attack whichever framing is unstated.
- **Fix:** Report both: quantum converts the cooperative payoff (4/3) into an enforceable Nash equilibrium, whereas the only classical equilibrium is the tragedy outcome (1/3). Frame advantage as equilibrium selection, not raw payoff gain.

#### [CLAIMS] RESOLVED (traceability note)
- **Claim:** Hypothesis "(Q,Q,Q) → V/2 = 2.0" (Month-2 spec §2.4).
- **Source:** Refuted by simulation: actual = 4/3. Spec §2.4 correctly marked it a hypothesis to measure. No doc currently claims 2.0 for N=3.
- **Fix:** None; ensure no future doc reintroduces 2.0 for N>2.

### Layer 4 — Interface Contracts

- **Actual:** Producer returns correct shape; consumer indexes `probs[i]` with no length/normalisation assertion (`payoffs.py:72-74`). - **Fix:** Guard at top of `expected_payoff`: `assert probs.shape == (2**N,) and np.isclose(probs.sum(), 1.0)`.
